# Real MongoDB and Atlas: risk register

**Nothing in this file has been run against real MongoDB or Atlas.** The machine that wrote
it has no MongoDB and no Docker. Every test that needs a server skips there, and nothing
about Atlas Vector Search has been checked. Where this file says what MongoDB or Atlas
does, that comes from the MongoDB documentation or from reading the driver source. A
"Real MongoDB / Atlas" cell that says *unknown, unverified* means exactly that. Each row
has the command that checks it on a real database.

The API has only ever run on mongomock (tests, `STITCH_FAKE_DB=1`, `python -m seed.serve`).
This file lists every place where the code branches on mongomock versus a real server, and
every class of difference mongomock hides, with what happens to the demo if the real
behaviour differs.

## Morning order of work

Run everything from `api/`. Set `MONGODB_URI` in the shell or in `api/.env`. With only the
`.env` file, add `--env-file .env` after `uv run`, as in seed/README.md. Never paste the URI
into a chat, an issue or a log: the commands below never print it.

1. **Preflight** (connects, then reports the version, indexes and vector indexes, and round-trips one throwaway family):
   `cd api && uv run python -m seed.preflight`
2. **Disposable-database tests.** `MONGODB_URI_TEST` must point at the same cluster or at
   another one. The fixture creates and drops its own `stitch_test_<hex>` databases, so the
   database user needs read/write on *any* database. That is the Atlas UI default, but a
   user scoped to `stitch` only will fail every test with `Unauthorized`.
   `cd api && MONGODB_URI_TEST='<disposable db uri>' uv run pytest -q tests/data/test_real_mongo.py tests/data/test_real_mongo_risks.py`
   On an **M0** cluster, add `-k "not vector_indexes_declare and not queryable"` unless the
   cluster is a separate one. Those two tests create four search indexes in throwaway
   databases, and M0 allows three per cluster (R7).
3. **Seed the demo family.** It is safe to re-run: the command does nothing when the
   family is already complete, and `--reset` rebuilds only the demo documents:
   `cd api && uv run python -m seed.demo`
4. **Wait for the vector indexes**:
   `cd api && uv run python -m seed.preflight --wait 180`

If Atlas will not create the vector indexes from the driver (R7, R34), create them in the
Atlas UI under Atlas Search, Create Index, Vector Search, JSON editor. Use database
`stitch` (or `MONGODB_DB`), collections `memories`, `props` and `sets`, and index names
`memories_vector`, `props_vector` and `sets_vector`. Each index gets this definition (set
`numDimensions` to `EMBEDDING_DIM` when that is set):

```json
{"fields": [{"type": "vector", "path": "embedding", "numDimensions": 1024, "similarity": "cosine"},
            {"type": "filter", "path": "familyId"}]}
```

## Status values

- **fixed in this PR**: the code changed here, and a test that failed before the change now passes offline.
- **covered by an existing test**: a real-server test already exists. It still has to be *run*; nothing here has run it.
- **needs a real-DB run**: the risk is open until the command passes against a real server.
- **known limitation**: accepted for the demo. The command shows the current behaviour.
- **fix pending (wave 2)**: the fix belongs in a file this task does not own (`db/client.py`, `db/families.py`). The exact change is given.

Each verify command runs on its own. `<disposable db uri>` is a URI whose user may create
and drop databases; the tests never touch the database named in it.
